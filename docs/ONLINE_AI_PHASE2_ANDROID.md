# Online AI and Flipper display provenance — Phase 2

This is **Android source** for a side-by-side test APK, not a production release.

## User-facing behavior

The Bluetooth screen now exposes `OFFLINE`, `HYBRID` and `ONLINE` modes
plus a one-session cloud authorization checkbox without opening Advanced.
It clearly distinguishes a *stored Worker configuration* from an online
provider that has actually answered. A button in Advanced sends **one
explicit harmless test prompt** through the configured Worker, consuming
only any quota associated with that user action.

- OFFLINE: requests always stay on Android, no internet AI.
- HYBRID: use available local inference first. If unsupported/failing,
  use the configured HTTPS cloud Worker **only with visible-screen consent**.
  A cloud error may return to the on-device AI/diagnostic fallback.
- ONLINE: use the cloud Worker only with consent; errors do not impersonate
  successful local inference.
- The actual Flipper AI1 ANSWER payload receives an accurate prefix:
  `CLOUD: `, `OFFLINE: `, or `OFFLINE FALLBACK: `, bounded by the
  existing 180-byte wire frame and Flipper screen.
- When Android UI moves to background, consent is revoked, cloud requests
  are cancelled where possible, and the existing BLE link stays alive.

## Deployment requirements (NOT yet completed)

The private Flipper firmware repo PR #85 contains a Cloudflare Worker
source upgrade: Cloudflare Workers AI with `AI` binding and a model that
Cloudflare currently lists for Workers Free, with an optional separately
funded OpenAI API provider only when configured. The user still needs to
deploy the Worker to an account and set an owner-chosen `DEVICE_TOKEN`
secret; the Android app must save that Worker's HTTPS `/ask` URL and the
corresponding token. No cloud endpoint or token was fabricated, and no
remote provider test or deployment was performed.

Private GitHub PR: https://github.com/cruefan94/Flipper-AI-Momentum-/pull/85

## Acceptance

1. Test the Android APK side-by-side. Existing signed production APK stays
   untouched. Set OFFLINE and confirm Flipper response says OFFLINE.
2. Configure own Cloudflare Worker and secret; confirm HTTPS health and
   authenticated single test response from Android.
3. Choose ONLINE, authorize explicitly, send unique Flipper ASK, and verify
   `CLOUD:` reply generated by the configured model.
4. Choose HYBRID and verify on-device first, and intentional cloud failover
   only for unsupported prompts with permission.
5. Toggle consent OFF, lock Android UI, disconnect Bluetooth, and confirm no
   new cloud requests and no stale replies cross a reconnect.
6. Check Worker Free quota via dashboard; never approve paid usage without
   explicit user action.

No Pi, new firmware, custom Flipper BLE service, or ESP32-S3 purchase required.
